Antinuke es la capa de emergencia de Vyrron para acciones destructivas del servidor. Está diseñado para reducir el radio de daño de cuentas comprometidas, bots maliciosos y cambios masivos. La implementación monitorea 25 tipos de eventos, incluyendo acciones en canales, roles, webhooks, integraciones, baneos, expulsiones, desbaneos, añadir bots, menciones masivas, roles de miembros, prune, invitaciones peligrosas y eventos programados.

## Actívalo de forma segura

<Steps>
  <Step title="Configura el logging primero">
    Ejecuta `/logging setup` y `/logging enable` para que el staff pueda ver a qué está reaccionando antinuke.
  </Step>
  <Step title="Revisa el límite de confianza">
    Usa `/whitelist` y `/extraowner manage` para inspeccionar quién puede saltarse la protección. Solo el propietario del servidor o un propietario adicional puede activar, desactivar, resetear o gestionar el límite de confianza del antinuke. Mantén ambas listas intencionalmente pequeñas.
  </Step>
  <Step title="Activa y verifica">
    Ejecuta `/antinuke enable`, luego `/antinuke status` para confirmar los módulos activos. Al activarlo también se prepara el rol `Vyrron Antinuke` usado por el sistema de protección; sigue la instrucción de jerarquía de la respuesta.
  </Step>
</Steps>

## Comandos

| Comando | Para qué usarlo |
| --- | --- |
| `/antinuke enable` | Activar protección |
| `/antinuke disable` | Pausar protección |
| `/antinuke config` | Ver configuración de antinuke |
| `/antinuke status` | Ver módulos de protección activos |
| `/antinuke reset` | Borrar configuración de antinuke |
| `/whitelist add` | Añadir un usuario o rol |
| `/whitelist remove` | Eliminar un usuario o rol |
| `/whitelist` | Gestionar la lista blanca interactivamente |
| `/extraowner add` | Añadir un propietario adicional |
| `/extraowner remove` | Eliminar un propietario adicional |
| `/extraowner manage` | Gestionar propietarios adicionales interactivamente |
| `/extraowner reset` | Eliminar todos los propietarios adicionales |

<Warning>
  No añadas un rol completo del staff a la lista blanca del antinuke sin revisar quién tiene ese rol. Una cuenta de confianza comprometida puede saltarse la protección que pretendías añadir. Esto no reemplaza la revisión del audit-log de Discord ni un diseño de roles de staff con mínimo privilegio.
</Warning>

## Respuesta a incidentes

1. Comprueba `/antinuke status`.
2. Revisa los últimos logs de eventos.
3. Elimina entradas sospechosas de la lista blanca o de propietarios adicionales.
4. Pausa la automatización que pueda estar contribuyendo al incidente.
5. Usa `/antinuke disable` solo cuando entiendas las consecuencias y estés investigando activamente.
